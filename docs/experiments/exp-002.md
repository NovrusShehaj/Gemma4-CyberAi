# exp-002 — First real fine-tune: gemma3-cyber:v0.2

> **Status:** designed and pre-registered 2026-08-25, **before** the training run.
> Training itself runs in the cloud (free Colab/Kaggle T4/L4) per `docs/decisions.md` Q2.
> This document fixes the hypothesis and the bar before any candidate exists.

## 0. Correcting the record (important)

`gemma3-cyber:v0.1` was **never fine-tuned**. Its `Modelfile` is `FROM gemma3:4b` with a
custom system prompt only; `experiments/exp-001-gemma3-cyber-v0.1/` responses are 66/67
identical to the base model and its scorecard equals the base scorecard. The observed
"Kerberoasting → T1060" hallucination is therefore **base-model** behavior. **exp-002 is
the project's first real training experiment.**

## 1. Hypothesis

> **If** we fine-tune `gemma3:4b` on `sft_v0.2` (277 answer-diverse examples that teach
> exact ATT&CK IDs via contrastive correction and reinforce hallucination refusal /
> insufficient-evidence restraint), **then** hallucination resistance and ATT&CK-ID
> precision will improve materially (e.g. Kerberoasting answered as **T1558.003 /
> Credential Access**, not T1060/T1068), **because** the base model already has the
> descriptive knowledge but was never trained on the exact identifiers or on flagging
> fabricated premises — and it will do so **without** regressing the categories the base
> model already handles.

## 2. Design

| Field | Value |
|---|---|
| **Control** | `gemma3:4b` (frozen anchor), temp 0, seed 0, `num_predict` 512, baseline system prompt |
| **Treatment** | `gemma3-cyber:v0.2` (QLoRA adapter merged → GGUF Q4_K_M), same inference config |
| **Dataset** | `data/training/sft_v0.2.jsonl` (277 items, 277 unique answers, 15 task types, CC-BY-4.0, clean vs all eval sets) |
| **Training** | `configs/training/qlora_gemma3_4b_v0.2.yaml`; QLoRA r=16, 3 epochs, seq_len 1024, effective batch 8; `notebooks/colab_qlora_training.ipynb` |
| **Benchmarks** | `benchmark_v2` (frozen do-no-harm anchor) **and** `benchmark_v3` (targeted sensitivity: ATT&CK precision + factual scorer) |
| **Split** | held-out `test` for the final pre-registered comparison; `dev` for iteration only |

Because v3 uses a new `factual` scorer and a deliberately hard, skewed distribution, **v3
is not comparable to v2 head-to-head**. Report v2 and v3 separately (see §4).

## 3. Metrics

**Primary (unchanged from the pre-registered v2 criteria):** hallucination-resistance
pass_rate on `benchmark_v2` (base = 0.000). Bars: **≥ +33 pp** on `test` subset **and
≥ +50 pp** over the full 8-item category (`configs/eval_success_criteria.md` §4.1).

**Primary (new, v3):** ATT&CK-precision pass_rate on `benchmark_v3` `attack_mapping`
(factual + mcq items), and the flagship item `v3-attack-kerberoasting-t1060-trap` must
flip **fail → pass** (i.e. asserts T1558.003, forbids T1060/T1068).

**Secondary:** v3 `false_premise` and `hallucination` pass_rate; v2 combined
uncertainty-behavior; v2/v3 mean_score; per-category pass_rate.

**Guard (do-no-harm, unchanged):** v2 `test` overall pass_rate ≥ **0.913**;
`insufficient_evidence` (v2 test baseline 1.000) must not regress; no v2 category drops by
more than one item's worth (`configs/eval_success_criteria.md` §4.2–4.3).

## 4. Pre-registered success criteria

The experiment measures **both arms on both benchmarks** (base is the v3 control, since no
base-on-v3 number exists yet). The candidate **passes** iff all hold:

1. **v2 hallucination** improves ≥ +33 pp (test) and ≥ +50 pp (full category). *[frozen]*
2. **v3 ATT&CK precision** (`attack_mapping` pass_rate) improves ≥ **+40 pp** over the
   base-on-v3 control, **and** the Kerberoasting T1060 trap flips fail → pass.
3. **v3 false-premise** pass_rate improves ≥ **+33 pp** over the base-on-v3 control.
4. **Do-no-harm:** v2 `test` overall ≥ 0.913, `insufficient_evidence` not regressed, no
   category regression beyond one item.

**Failure thresholds:** if (1) or (2) is not met, the intervention did not fix the target
— record the negative result; do not move goalposts. If hallucination/ATT&CK improve but
(4) fails, treat as **not passing** (a gain bought by catastrophic forgetting) and iterate
one variable at a time.

## 5. Reproducibility / artifacts

Write under `experiments/exp-002-gemma3-cyber-v0.2/`: base and candidate `results.json` +
`scorecard.md` for v2-test and v3-test, the merged adapter hash, the training config, and
the exact commit of scorers used (must match across arms). Raw per-item responses are
stored so re-scoring needs no re-inference.

## 6. Commands (run after cloud training produces the GGUF)

```bash
# Build/refresh instruments (deterministic)
python -m gemma_cyber.data.builder_v2            # -> data/training/sft_v0.2.jsonl
python scripts/build_benchmark_v3.py             # -> data/evaluation/benchmark_v3.jsonl

# Gate the data
python scripts/validate_dataset.py --dataset data/training/sft_v0.2.jsonl \
    --check-contamination data/evaluation/benchmark_v1.jsonl data/evaluation/benchmark_v2.jsonl \
    --threshold 0.5

# Control (base) — both benchmarks, test split
python scripts/run_baseline.py --model gemma3:4b --benchmark data/evaluation/benchmark_v2.jsonl \
    --split test --out experiments/exp-002-gemma3-cyber-v0.2/base-v2-test
python scripts/run_baseline.py --model gemma3:4b --benchmark data/evaluation/benchmark_v3.jsonl \
    --split test --out experiments/exp-002-gemma3-cyber-v0.2/base-v3-test

# Treatment (v0.2) — both benchmarks, test split
python scripts/run_baseline.py --model gemma3-cyber:v0.2 --benchmark data/evaluation/benchmark_v2.jsonl \
    --split test --out experiments/exp-002-gemma3-cyber-v0.2/v0.2-v2-test
python scripts/run_baseline.py --model gemma3-cyber:v0.2 --benchmark data/evaluation/benchmark_v3.jsonl \
    --split test --out experiments/exp-002-gemma3-cyber-v0.2/v0.2-v3-test
```

## 7. Known risks

- **Small n:** v2 `test` hallucination n=3; v3 `test` n=12. Report deltas with a caveat on
  the tiny per-category n; a sub-CI delta is "no measurable effect", not a trend.
- **Overfitting:** 277 examples on a 4B model over 3 epochs can memorize. Watch for v2
  do-no-harm regression as the overfitting signal; if it appears, reduce epochs/LR first.
- **Judge:** the judge rubric changed to `judge-v2`; re-run calibration before citing judge
  numbers (see `docs/judge.md`). Deterministic scorers remain the primary, reproducible
  numbers.
- **Gemma-3 formatting:** verify the sample printed by the training cell looks correct
  (`<start_of_turn>user … <end_of_turn><start_of_turn>model …`) before the full run.
